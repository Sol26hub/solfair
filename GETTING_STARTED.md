# 🚀 Подробная инструкция по запуску (для новичков)

Эта инструкция рассчитана на то, что вы **никогда не работали с Solana/Rust/Anchor**.
Мы пройдём весь путь маленькими шагами: от установки программ до реальной покупки
билета и получения приза в тестовой сети (devnet — это "тренировочная" копия
Solana, где SOL ничего не стоит и раздаётся бесплатно).

Инструкция для **macOS** и **Linux**. Если у вас **Windows** — сначала установите
WSL2 (Windows Subsystem for Linux): откройте PowerShell от имени администратора,
выполните `wsl --install`, перезагрузите компьютер, а дальше все команды ниже
выполняйте внутри открывшегося окна Ubuntu.

---

## Часть 0. Что вообще происходит

- **Rust** — язык, на котором написан смарт-контракт (программа) лотереи.
- **Solana CLI** — консольная утилита для общения с блокчейном Solana.
- **Anchor** — фреймворк поверх Solana, упрощающий написание и сборку программ.
- **Node.js / npm** — нужны для скриптов деплоя и веб-интерфейса (фронтенда).
- **Devnet** — публичная тестовая сеть Solana. Все действия ниже происходят там,
  реальные деньги не участвуют.

Весь путь выглядит так:
1. Ставим инструменты.
2. Собираем Rust-программу → получаем **Program ID**.
3. Прописываем этот ID в коде и пересобираем.
4. Деплоим программу в devnet.
5. Инициализируем первую лотерею (скрипт создаёт аккаунт лотереи в блокчейне).
6. Запускаем сайт (фронтенд) и играем.

## Часть 1. Установка инструментов

Открываем терминал и выполняем по очереди. После каждой команды дожидаемся,
пока она полностью завершится (иногда это 2–10 минут).

### 1.1. Rust

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```
Когда появится меню — нажмите **Enter** (выбор "1) Proceed with installation (default)").

После установки перезапустите терминал или выполните:
```bash
source "$HOME/.cargo/env"
```

Проверка:
```bash
rustc --version
```
Должно вывести что-то вроде `rustc 1.79.0 (...)`. Если команда не найдена —
перезапустите терминал полностью и попробуйте снова.

### 1.2. Solana CLI

```bash
sh -c "$(curl -sSfL https://release.solana.com/v1.18.0/install)"
```

В конце установщик попросит добавить путь в `PATH` — выполните команду,
которую он покажет на экране (обычно похожа на):
```bash
export PATH="$HOME/.local/share/solana/install/active_release/bin:$PATH"
```
Чтобы не делать это в каждом новом терминале, добавьте эту же строку в конец
файла `~/.bashrc` (или `~/.zshrc`, если у вас zsh — по умолчанию на macOS):
```bash
echo 'export PATH="$HOME/.local/share/solana/install/active_release/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

Проверка:
```bash
solana --version
```
Ожидаем: `solana-cli 1.18.0 (...)`.

### 1.3. Node.js (18 версии или новее)

Проще всего через [nvm](https://github.com/nvm-sh/nvm):
```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.zshrc   # или ~/.bashrc
nvm install 20
nvm use 20
```
Проверка:
```bash
node --version   # v20.x.x
npm --version    # 10.x.x
```

### 1.4. Anchor (через avm — Anchor Version Manager)

```bash
cargo install --git https://github.com/coral-xyz/anchor avm --locked
avm install 0.30.1
avm use 0.30.1
```
Это самый долгий шаг (компилируется из исходников, может занять 5–15 минут).
Если увидите ошибки про недостающие системные библиотеки на Linux, выполните:
```bash
sudo apt-get update && sudo apt-get install -y build-essential pkg-config libudev-dev llvm libclang-dev
```
и повторите команду `cargo install ...` ещё раз.

Проверка:
```bash
anchor --version
```
Ожидаем: `anchor-cli 0.30.1`.

## Часть 2. Готовим кошелёк и тестовые SOL

### 2.1. Создаём локальный кошелёк (для деплоя из терминала)

```bash
solana-keygen new --outfile ~/.config/solana/id.json
```
Вас спросят пароль (passphrase) — можно просто нажать Enter дважды, чтобы
оставить пустым (это ок для тестового devnet-кошелька, **не используйте** это
для настоящих денег в mainnet).

Программа выведет ваш публичный адрес (Pubkey), например:
```
pubkey: 7xKX...9fQ2
```
Это адрес вашего тестового кошелька — он нам понадобится позже.

### 2.2. Переключаемся на devnet

```bash
solana config set --url devnet
```
Проверка:
```bash
solana config get
```
В строке `RPC URL` должно быть `https://api.devnet.solana.com`.

### 2.3. Получаем тестовые SOL (бесплатно)

```bash
solana airdrop 2
```
Если увидите ошибку `429 Too Many Requests` — devnet-кран перегружен, подождите
минуту и попробуйте снова, либо получите SOL через веб-кран:
https://faucet.solana.com (вставьте туда ваш Pubkey из шага 2.1).

Проверка баланса:
```bash
solana balance
```
Должно показать что-то вроде `2 SOL`.

## Часть 3. Распаковываем проект и ставим зависимости

Распакуйте архив `solana-lottery`, перейдите в папку:
```bash
cd путь/к/solana-lottery
```

Устанавливаем зависимости для тестов/скриптов (в корне проекта):
```bash
npm install
```

Устанавливаем зависимости фронтенда:
```bash
cd app
npm install
cd ..
```

Оба раза это может занять пару минут — npm скачивает пакеты.

## Часть 4. Собираем и деплоим смарт-контракт

### 4.1. Первая сборка

```bash
cd program
anchor build
```
Первая сборка самая долгая (5–15 минут) — компилируются все Rust-зависимости.
В конце должно появиться `Finished` без ошибок (warnings — это нормально,
ошибки (`error[...]`) — не нормально, см. раздел "Проблемы" в конце).

### 4.2. Получаем реальный Program ID

```bash
anchor keys list
```
Вы увидите строку вида:
```
solana_lottery: 9WzDXwBbmkg8ZTbNMqUxvQRAyrZzDsGYdLVL9zYtAWWM
```
Это ваш **уникальный** ID программы (у вас он будет свой, не такой, как в
примере). Скопируйте его.

### 4.3. Прописываем Program ID в трёх местах

1. `program/src/lib.rs` — найдите строку:
   ```rust
   declare_id!("LoTTery1111111111111111111111111111111111");
   ```
   замените плейсхолдер на ваш реальный ID из шага 4.2.

2. `Anchor.toml` (в корне проекта) — найдите:
   ```toml
   [programs.devnet]
   solana_lottery = "LoTTery1111111111111111111111111111111111"
   ```
   и тоже замените на ваш ID.

3. Пока пропустите `app/src/config.json` и `app/src/idl.json` — их автоматически
   обновит скрипт `deploy.ts` на шаге 5.2, руками трогать не нужно.

### 4.4. Пересобираем с новым ID

```bash
anchor build
```
(мы всё ещё в папке `program`). Теперь сборка будет намного быстрее (1–2 минуты),
так как зависимости уже скачаны.

### 4.5. Деплой в devnet

Убедитесь, что на кошельке достаточно SOL для деплоя (обычно 2–4 SOL):
```bash
solana balance
```
Если мало — повторите `solana airdrop 2` (можно несколько раз с паузами).

Деплоим:
```bash
anchor deploy --provider.cluster devnet
```
Это загружает скомпилированную программу в блокчейн и может занять 1–3 минуты.
В конце должна появиться строка:
```
Program Id: <ваш Program ID>
Deploy success
```

Если увидите ошибку `insufficient funds` — сделайте ещё airdrop и повторите.

## Часть 5. Инициализация первой лотереи

Возвращаемся в корень проекта:
```bash
cd ..
```

### 5.1. Копируем сгенерированный IDL для фронтенда

IDL (Interface Description Language) — файл-описание "какие есть функции у
программы и какие у них аргументы". Anchor генерирует его автоматически при
сборке. Скопируйте его поверх файла-заглушки:
```bash
cp program/target/idl/solana_lottery.json app/src/idl.json
```

### 5.2. Запускаем скрипт инициализации

```bash
npx ts-node scripts/deploy.ts
```
Скрипт:
- создаёт аккаунт лотереи в блокчейне (цена билета — 0.1 SOL, максимум
  100 билетов, продолжительность — 24 часа — эти значения можно поменять
  прямо в файле `scripts/deploy.ts` перед запуском, если нужно другое);
- печатает адреса Lottery PDA и Escrow PDA;
- автоматически перезаписывает `app/src/config.json` этими адресами, чтобы
  фронтенд знал, с какой лотереей работать.

Ожидаемый вывод:
```
Program ID:    9WzD...
Authority:     7xKX...
Lottery PDA:   ...
Escrow PDA:    ...
Ticket price:  0.1 SOL
Max tickets:   100

✅ Lottery initialized
Transaction:  5h8s...
Wrote frontend config to .../app/src/config.json
```

Если хотите **изменить параметры лотереи** (цену билета, число билетов,
длительность) — откройте `scripts/deploy.ts`, найдите переменные
`ticketPriceLamports`, `maxTickets`, `durationSeconds` и поменяйте значения
до запуска скрипта. Помните: 1 SOL = 1 000 000 000 lamports.

## Часть 6. Запускаем сайт

```bash
cd app
npm run dev
```
В терминале появится что-то вроде:
```
  VITE ready in 400 ms
  ➜  Local:   http://localhost:5173/
```
Откройте `http://localhost:5173` в браузере.

### 6.1. Ставим кошелёк-расширение для браузера

Если у вас ещё нет кошелька в браузере — поставьте **Phantom**
(https://phantom.app) или **Solflare** (https://solflare.com), создайте
новый кошелёк (для теста, не используйте кошелёк с реальными деньгами).

В настройках кошелька переключите сеть на **Devnet** (обычно: иконка
настроек → Developer Settings → Change Network → Devnet).

Пополните этот кошелёк тестовыми SOL так же, как в шаге 2.3 — введите его
адрес на https://faucet.solana.com, либо командой:
```bash
solana airdrop 2 <адрес_кошелька_из_Phantom>
```

### 6.2. Пробуем купить билет

На сайте нажмите **"Select Wallet"** → выберите Phantom/Solflare → разрешите
подключение. Дальше:
1. Нажмите **"Buy a ticket"** — Phantom попросит подтвердить транзакцию,
   подтвердите. Через пару секунд статус обновится, появится "You hold
   ticket #00".
2. Чтобы протестировать розыгрыш с несколькими участниками, создайте ещё
   1–2 кошелька в Phantom (кнопка добавления аккаунта), пополните их через
   faucet и купите билеты с них тоже (переключаясь между аккаунтами).

### 6.3. Розыгрыш победителя

Розыгрыш — двухшаговый (это специально: так проверяемая случайность не
зависит от того, кто именно нажимает кнопку):
1. Как только билеты закончились (или истекло время), на сайте появится
   кнопка **"Request the draw"** — нажмите её. Это «фиксирует» будущий слот
   блокчейна, хэш которого станет источником случайности.
2. Подождите ~10–15 секунд (пока пройдёт пара слотов Solana).
3. Обновите страницу / подождите автообновление — появится следующий шаг
   розыгрыша. Если кнопки "Draw winner" пока нет в интерфейсе — это нормально
   для самой первой версии фронтенда, розыгрыш можно вызвать и вручную через
   `anchor test`/консоль, см. `IMPLEMENTATION_NOTES.md`.
4. После розыгрыша на сайте появится "Winning ticket: #XX".

### 6.4. Получение приза

Если ваш кошелёк держит выигрышный билет — появится кнопка **"Claim your
prize"**. Нажмите, подтвердите транзакцию в Phantom — SOL придёт на ваш
кошелёк (98% от банка), 2% уйдут на адрес treasury (по умолчанию это
адрес-заглушка, из-за чего claim_prize завершится ошибкой, пока вы не
замените `TREASURY_PLACEHOLDER` в `app/src/App.jsx` на настоящий адрес —
см. `IMPLEMENTATION_NOTES.md`, пункт 3).

## Часть 7. Автоматические тесты (необязательно, но полезно)

Тесты поднимают локальный тестовый валидатор Solana на вашей машине (не
трогают devnet) и проверяют покупку билетов, запрет повторного билета,
sold-out, отмену и возврат средств:

```bash
cd program
anchor test
```
Ожидаем в конце что-то вроде:
```
  solana-lottery
    ✔ initializes a lottery
    ✔ sells a ticket and moves SOL into escrow
    ✔ rejects a second ticket from the same wallet
    ✔ rejects purchases once the lottery is sold out
    cancellation + refund flow
      ✔ only the authority can cancel
      ✔ cancels the lottery and refunds the ticket holder
      ✔ rejects a double refund claim

  7 passing
```

## Часть 8. Частые проблемы и их решения

| Проблема | Решение |
|---|---|
| `command not found: anchor` / `solana` / `rustc` | Терминал не видит `PATH`. Перезапустите терминал полностью или заново выполните `source ~/.zshrc` (`~/.bashrc`). |
| `Error: insufficient funds` при деплое | Сделайте `solana airdrop 2` ещё раз (можно несколько раз с паузой в 30–60 сек). |
| `429 Too Many Requests` при airdrop | Devnet-кран перегружен — подождите или используйте https://faucet.solana.com |
| `anchor build` падает с ошибками про `libudev`/`pkg-config` (Linux) | Установите `sudo apt-get install -y build-essential pkg-config libudev-dev llvm libclang-dev` и повторите. |
| Сайт открывается, но лотерея не грузится ("Could not load lottery state") | Проверьте, что `app/src/config.json` и `app/src/idl.json` обновились после шагов 4.3, 5.1, 5.2 — и что вы задеплоили именно тот Program ID, который прописан в `Anchor.toml`/`lib.rs`. |
| Phantom не видит devnet-баланс | Убедитесь, что в настройках Phantom выбрана сеть **Devnet**, а не Mainnet. |
| `Transaction simulation failed: custom program error: 0x...` | Это ошибка из кода лотереи (например, "лотерея уже распродана" или "билет уже куплен этим кошельком") — посмотрите текст ошибки в консоли браузера (F12 → Console), там будет читаемое сообщение из `LotteryError`. |
